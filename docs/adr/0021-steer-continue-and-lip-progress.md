# ADR 0021：运行中插话、“继续”与唇条里的计划进度

- 状态：已采纳（2026-11-19）

## 背景

运行中输入框不能发送，只能停止；想补一句要求只能停掉重来。回复出错后的“重试”会把上一句用户消息原样再发一遍，被停止的回复没有接着做的办法。ADR 0019 把计划进度移到输入框上方的独立卡片，占用对话空间。

用户要求参考 Codex 的实现：运行中发送直接插入当前对话，不做排队；结束后不要“重试”，改为“继续”，且“继续”不是重发上一句；计划进度放回唇条，只在鼠标悬停时展开步骤列表。

Codex 的做法（openai/codex：`core/src/session/turn.rs` 在每次模型采样前取出 pending input 写进历史；TUI 的 Enter 为 steer，待插入内容显示在输入框附近，core 记为用户消息后才转为正式消息；中断时把未写入的插话立即提交）。Core（pi）已原生支持同样的语义：`prompt` 的 `streamingBehavior: "steer"`、`clear_queue`、`queue_update` 事件，插话在当前工具调用结束、下一次模型请求前投递。

## 决定

### 插话（不排队）

- 运行中输入框照常可写；有内容时停止按钮换成发送按钮（无障碍名“发送（插入当前对话）”），Enter 同样发送。发送用 `prompt` + `streamingBehavior: "steer"`（不用单独的 `steer` 命令：Core 恰好已空闲时它按普通消息开始新一轮，消息不会滞留在队列里）。前端不使用 `follow_up`。
- 发出后立即在对话末尾显示“待插入”气泡（半透明，下方注明“将在当前步骤完成后插入”），输入框在 Core 受理后清空；Core 写入（多出一条用户消息）后待插入气泡换成正式气泡，回复接在新的用户消息之后。按发出时的用户消息条数判断写入，不依赖文本比对（Core 会展开技能命令与提示模板）。
- 停止：先 `clear_queue` 取回还没写入的插话，再 `abort`；一轮结束后把取回的插话（多条以空行合并，图片合并）作为一条新消息立即发出。
- 会话状态新增 `steering`（`queue_update` 整体替换）。

### 继续

- 新增第一方扩展模块 `primus-continue`，只注册命令 `/primus-continue`：写入一条 `display: false` 的自定义消息（customType 同名，内容为继续提示）并 `triggerTurn`。命令处理放到下一个事件循环再触发新一轮，避免 `prompt` 的响应要等这一轮跑完。
- 继续提示说明：中断前那段未完成的回复不会保留（Core 回放时跳过 `stopReason` 为 `error` / `aborted` 的助手消息），请按已有对话与工具结果从中断前的进度继续，不要重复已完成的操作、不要从头回答。
- 界面：错误卡片的“重试”换成“继续”；被停止的回复在“已停止”旁、被截断的回复在提示旁显示“继续”。都只在最后一轮、空闲时出现。自定义消息不显示，继续的回复接在同一轮里，没有新的用户气泡。

### 唇条里的计划进度

- 计划进度回到唇条正中（左侧仍是分支与工作区）：进度环 +“还剩 N 步”+ 箭头 + 当前步骤（流光，过长截断）。
- 鼠标悬停或键盘聚焦时，在唇条上方弹出全部步骤（沿用 ADR 0019 的步骤样式：胶囊边框、打勾划线、跳过斜杠、超过 8 步内部滚动）；移开即收起，不需要点击。纯 CSS（`group-hover` / `group-focus-within`），弹层底部留透明桥接，鼠标移向列表时不断开。
- 完成后淡出、让位规则不变。不能选工作区时，有待办也显示唇条。ADR 0019 的独立进度卡片取消。

## 后果

- 运行中补充要求不再需要停止重来；插话在工具调用之间生效，不会打断正在执行的命令。
- “继续”不重复用户消息，历史里多一条不显示的自定义消息。
- mock 平台支持插话入队与投递（插在本轮 `agent_end` 前）、`clear_queue` 与 `/primus-continue`。
